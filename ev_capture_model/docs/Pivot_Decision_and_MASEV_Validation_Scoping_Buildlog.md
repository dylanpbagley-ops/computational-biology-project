# Pivot Decision and MASEV Validation Scoping — Buildlog

This document is the full story of one session (August 28, 2026, immediately following the AND-gate/novelty-assessment session): the user's honest dissatisfaction with the project's competitive potential, the research done to answer it directly rather than reassure reflexively, the decision to pivot part of the project, and the concrete real-data source identified to build that pivot on. No code was written this session — this was entirely research, verification, and scoping. `EV-Capture-CURRENT.md` points here for the full account; only the decisions and open items are carried into that file directly.

## How this session started

The prior session had ended with the user asking, bluntly, whether options A (get real external validation data, e.g. by emailing the Lennon/Mizenko/Chiodi paper authors) and D (find a wet-lab mentor) were worth pursuing before starting the write-up. The user stated three things directly: they believed external validation had already been tried and failed; they had personally already tried and struggled to find a wet-lab mentor; and — most importantly — they were **not satisfied** with the project's results, believed the project as scoped lacked the potential to be as competitive as they wanted (due to the missing external validation), and separately suspected that even WITH external validation, nothing "truly impactful enough" had been found. They explicitly invited correction if this pessimism was wrong, and asked for a genuine pivot exploration that reuses existing work, given real urgency (this is their only ISEF year) and explicit determination to "go all the way."

## Fact-check: was external validation actually tried and failed?

Grepped every archived handoff file (`v5.md` through `v10.md`, and by extension the practice continuing through `v15.md`) for the exact language about contacting the Carney/Mizenko lab. Found the identical sentence — "Open lead, not yet pursued... Deferred by choice, not ruled out" — appearing in every single session from v5 onward. **Confirmed: this was never attempted.** It was named as an open lead and explicitly, repeatedly deferred, across at minimum 11 sessions. This directly contradicts the user's memory of a failed attempt — a meaningful correction, since "never tried" and "tried and failed" imply very different odds going forward.

## The sobering technical wrinkle surfaced during fact-checking

Re-reading `k_intra_z_plausibility_bounds.py`'s own documentation confirmed something worth stating plainly: even a maximally generous outcome from contacting Mizenko/Carney (a fast, friendly, complete response) likely would NOT resolve the project's core identifiability gap. The specific missing quantity — the ExoView chip's antibody surface density (sigma) — is described in the project's own code documentation as "a proprietary commercial-platform detail that is not published anywhere findable (checked: paper's own methods, manufacturer specs, product literature)." This is a trade secret of the commercial platform vendor (NanoView/Unchained Labs), not something the paper's own authors necessarily have precise access to either. So the barrier to option A was reframed for the user: it isn't just "authors might not respond," it's "even a generous response likely doesn't contain the needed information."

## Research to ground the honest verdict

Rather than answer the user's "am I wrong to be pessimistic" question from impression, three real research threads were run:

1. **Field-level framing check**: searched for how the EV liquid-biopsy field itself names its biggest unsolved translation problems, and fetched the full text of a 2023 PMC review ("Future of Digital Assays to Resolve Clinical Heterogeneity of Single Extracellular Vesicles," PMC10174080). Found: EV heterogeneity is a real, recognized clinical-translation barrier, but the field's own commonly-cited barriers (standardization, preanalytical variability, multiplexed-readout chemistry, ML training-set size) are adjacent to, not identical to, this project's specific "rank capture targets by full receptor-count distribution, not just fold-change" framing. Nobody in that review frames distribution-shape-aware target ranking as a named methodological contribution, and nobody describes AND-gate/combinatorial CAPTURE (physically requiring simultaneous binding of two receptors) as an approach — all the review's described multiplexing is multiplexed READOUT after single-marker capture.

2. **The verdict delivered**: the user was told directly they were not wrong to be dissatisfied. The reasoning given: the generous reading is that this really is underexplored territory (a legitimate computational contribution, not reinvented ground); the harder, more important reading is that pure simulation without ever touching real per-vesicle joint data may not move the needle much for a field whose stated bottlenecks are calibration and standardization, not target-ranking methodology. A judge or reviewer would reasonably ask "how do you know this maps onto anything real," and the honest answer at that point was "we can't know, because sigma isn't identifiable and the joint AND-gate data doesn't exist." The user's instinct that this was a real ceiling, not a solvable rough edge, was confirmed as matching the independent research rather than corrected.

## ISEF structural pattern research (real winning projects, not impressions)

A subagent queried the Society for Science's public project abstract database (`abstracts.societyforscience.org`) directly, pulling full abstracts (not just titles) for six real 2024 Computational Biology & Bioinformatics award winners. Key finding, and the one that shaped the whole pivot direction: **"T-STM" (Ajeet Venkatesh, a tumor-microenvironment PDE/agent-based simulation calibrated against real TCGA data with genuinely strong statistics, r=0.78-0.91, significant survival hazard ratios) won only the LOWEST award tier (Fourth Award, $500).** Every First/Second Award winner in the same category went one step further: they used a model validated against real data to make a NEW, independently checkable claim (a specific count of newly-discovered mutations, a specific novel-molecule generation rate) — not just "my simulation reproduces what's already known." This became the concrete bar for the pivot: real external data plus a quantitative fit metric is necessary but not sufficient; a genuinely novel, checkable prediction on top of that is what separates minor from major awards.

## Pivot options generated and scored (0-100)

Four options were researched and scored for realistic ISEF+journal competitiveness given the ~6-month runway, no wet lab, and everything already built:

1. **Validate the model against SVAtlas real single-vesicle data (72).** Reuses the binding model, AND-gate machinery, and identifiability discipline; compares the model's predicted joint-marker distribution against a real published one.
2. **Same as (1), but go one step further and use the validated model to make a new, checkable prediction on held-out or different real data (85).** This directly targets the T-STM lesson — validation alone caps out low; a novel prediction on top of validation is what wins.
3. **Reframe as an open-source "distribution-aware marker ranking" toolkit, benchmarked across multiple real public single-EV datasets (78).** Higher journal fit, more engineering risk (heterogeneous per-study data formats).
4. **Pivot away from EV capture physics entirely toward an ML classifier on spectral/single-EV data for cancer diagnosis (48).** Feasible, well-trodden, but throws away nearly everything already built and drops into an already-crowded niche with no distinctive computational contribution.

**Decision, made by the user this session: commit to 1→2 as a single track (validate, then extend to a new prediction), keep 3 as a later stretch goal once 1/2 are solid, eliminate 4 entirely.** The user was explicit that combining options (not just picking one) was welcome, and this is what was chosen.

## Finding the real data source: SVAtlas

**SVAtlas** (Nucleic Acids Research, 2025, DOI 10.1093/nar/gkaf1189, `https://svatlas.org`) is a real, aggregated single-EV database spanning 75 published studies. Its data format ties multiple marker measurements to the same individual vesicle ID ("EV" column, long-format table with columns for sample, vesicle ID, marker name, count value, and group), filtered to vesicles expressing 2+ markers at count ≥3 — genuinely joint, per-vesicle, multi-marker data, unlike anything in the project's existing sources (Lennon's data is single-marker-only, digitized from separate scatter plots).

**Marker overlap confirmed**: SVAtlas has a dedicated Pancreatic Cancer disease page (9-10 projects, 6 source papers) listing HER2, GPC1, EpCAM, EGFR, PD-L1, CD9, CD63, CD81, CD47, CD98, CD29, TSG101, Syntenin-1, Alix, MUC1, Calnexin, ESR1, ER, CD41a, IGF1R. EGFR and MUC1 (a strong pancreatic-cancer-relevant substitute for CA19-9, which is not itself EV-surface-profiled anywhere in SVAtlas) are both present. CD9/CD63/CD81 are all present.

**Access mechanics discovered**: SVAtlas's rendered project/marker tables are JavaScript/AJAX-driven and not readable via plain text fetch, but the underlying DataTables JSON API endpoints were found directly by inspecting the page's inline script tags (via a raw, non-markdown-simplified fetch): `scripts/server_processing_project.php` (all 290 projects) and `scripts/server_processing_project_marker.php` (8,275 rows, every project's marker panel). These return real JSON without needing to download or unzip anything.

**The one narrowing finding**: three SVAtlas pancreatic projects (PRJ20230304_1, _2, _3, all tracing to PubMed 36870999) list CD9, CD63, CD81, EGFR, AND MUC1 together in the same marker panel — but tracing back to the underlying paper (see next section) showed EGFR/MUC1 and the tetraspanins were actually measured in two SEPARATE experiments on the same cell line (ASPC1), not one joint run. So the exact 5-marker joint dataset hoped for does not exist as a single measurement. The tetraspanin triplet (CD9/CD63/CD81) DOES exist as genuine joint per-vesicle data across four cell lines in one experiment, and this became the actual validation target.

**No downloadable raw file was ever opened.** The sandbox's shell (bash) network is behind a hard egress allowlist proxy that explicitly blocks svatlas.org (`curl` returned `403 blocked-by-allowlist`) — this is a sandbox-level restriction, not worked around. The built-in browser pane could reach the site (`preview_start` succeeded) but repeat `navigate` calls to the same origin failed intermittently and no actual file bytes were retrieved from the zip. All SVAtlas data used came from the JSON API text, not a downloaded/unzipped file — a real constraint for whoever picks this up next: if the raw per-project files themselves are needed later, this will require either a session with different network access, or manually downloading the file outside this environment and uploading it in.

## The actual validation source: the MASEV paper

Traced PRJ20230304_1/_2/_3 to their source paper: **Spitzberg, Ferguson, Yang, Peterson, Carlson & Weissleder, "Multiplexed analysis of EV reveals specific biomarker composition with diagnostic impact,"** *Nature Communications* 14:1239 (2023), DOI 10.1038/s41467-023-36932-z, PMID 36870999. Also exists as a bioRxiv preprint (10.1101/2022.06.17.496607) with identical content and openly viewable figures.

**Why this paper is a strong real-data foundation, confirmed by reading the full text directly (not a summary):**

- **True per-vesicle joint marker tracking, not just population statistics.** The method (MASEV — multiplexed analysis of EV) fixes vesicles to a glass surface and tracks the SAME individual vesicle across 5 cycles of stain/image/cleave-and-restain, using image registration (phase cross-correlation) to preserve identity. Retention was validated directly: ">99% EV retention across multiple cycles." This is a real, technically solid method for getting genuine joint multi-marker calls per vesicle, not an assumption.
- **The core validation experiment**: a 12-marker, 4-cycle panel was run jointly on four cell lines — PANC-1, CAPAN-2, ASPC1, and A549 — including all three tetraspanins (CD9, CD63, CD81) together with CD47, CD98, CD29, TSG101, Syntenin-1, Alix, and others, in ONE run. This produced real joint co-occurrence statistics.
- **Exact numbers extracted directly from Figure 4 (full Venn breakdown, screenshotted and read at full resolution from the bioRxiv preprint's own figure lightbox), for two of the four cell lines:**
  - **PANC-1**: No tetraspanin 24.8%, CD9 only 37.6%, CD81 only 4.6%, CD63 only 4.4%, CD81&CD9 11.2%, CD63&CD81 1.6%, CD63&CD9 10.6%, all three 5.1%.
  - **CAPAN-2**: No tetraspanin 52.6%, CD9 only 23.7%, CD81 only 7.5%, CD63 only 4.8%, CD81&CD9 4.4%, CD63&CD81 1.4%, CD63&CD9 3.5%, all three 2.0%.
  - **ASPC1 and A549**: only shown as color-coded stacked bar heatmaps (0/1/2/3-tetraspanin-count-per-vesicle) in the same figure, not broken out per individual marker combination in the text or the readable figure — exact numbers for these two were NOT successfully extracted this session (see "Open items" below).
- **Number of vesicles analyzed per cell line** (for statistical-power planning): PANC-1 8,500; CAPAN-2 4,600; ASPC1 14,000; A549 8,100.
- **No Data Availability or Code Availability statement exists in this paper at all** — confirmed by reading the complete full text via the PubMed MCP tool (not a parsing gap; the text runs cleanly from Introduction through the Reporting Summary line with no such section anywhere in between). No GEO/Zenodo/Figshare accession exists. This means: no raw per-vesicle table can be obtained from this paper by any means found this session — the published Figure 4 percentages themselves are the validation target, not a stand-in for a richer dataset that exists somewhere else.
- **EGFR/MUC1 caveat, confirmed directly from the Methods section**: these two markers were measured on ASPC1 cells via a SEPARATE immunogold electron-microscopy comparison experiment (not the 12-plex MASEV panel), for method-validation purposes only ("11% vs 7% of EV positive for EGFR, 3% vs 4% positive for MUC1... TEM vs MASEV, respectively" — a MASEV-vs-EM agreement check, not a joint EGFR/MUC1/tetraspanin measurement). So EGFR and MUC1 are NOT available jointly with the tetraspanins from this paper. The tetraspanin triplet is the real, available, joint validation target.

## Necessary scope adjustment this finding requires (important, flagged directly to the user)

The original tumor-selectivity framing (EGFR, CA19-9 — tumor-associated markers with a real tumor-vs-normal biology story) is NOT what this validation data covers. Tetraspanins (CD9/CD63/CD81) are general EV-membrane structural proteins tied to vesicle biogenesis, present at low and heterogeneous copy number for reasons unrelated to tumor biology — there is no "tumor should have more CD9 than normal" story the way there was for EGFR/CA19-9. This means the pivot validates a DIFFERENT claim than the project's original tumor-selectivity claims: "the model's predicted joint multi-marker distribution shape matches a real published one" is the new, validated claim; "the model's tumor-vs-normal selectivity predictions are validated" remains NOT true and should continue to be reported exactly as before — range-based, not independently confirmed. These two claims must stay clearly separated in any future write-up. This is a real, honest narrowing of scope, explicitly acknowledged rather than glossed over, consistent with the project's whole verification discipline.

## Step-back check performed this session (for the record)

Before committing further time, the user explicitly asked for a pause to check the direction was sound — an honest gut-check was given rather than reflexive encouragement: this direction genuinely reuses the AND-gate machinery (built to answer almost exactly this "joint multi-marker distribution" question, just previously aimed at EGFR/CA19-9), it directly closes the external-validation gap the ISEF research identified as real and consequential, and no red flags were found — but two honest caveats were raised and should NOT be forgotten: (a) this is validation against published SUMMARY STATISTICS, not a full raw-data reanalysis, which is a real but thinner form of external validation than getting an author's raw table would have been, and the write-up must describe it precisely as such; (b) the tetraspanin/tumor-selectivity scope split described above must be maintained throughout, not blurred for narrative convenience.

## CLOSEOUT (added a later session, August 29, 2026): every open item above resolved, plus a real raw-data upgrade this scoping session did not anticipate

This section closes out the five "Open items for the next session" listed above. All five were resolved, in a later session, in ways beyond what this scoping session expected — most importantly, item 5 ("SVAtlas's actual zip files were never opened") turned out to be possible after all, and produced a genuine upgrade from summary-statistic validation to real raw-per-vesicle-data validation for two of this project's checks. Full detail lives in `EV-Capture-CURRENT.md`'s own "What changed" history; this entry is just the closeout pointer.

1. **"Get exact ASPC1/A549 per-category percentages" — DONE.** The user manually downloaded the MASEV paper's own Supplementary Information PDF and uploaded it directly. Real marginal (single-marker) percentages for both cell lines were read directly from Supplementary Fig. 12. No real joint 8-category number exists anywhere in that PDF for these two cell lines (checked page-by-page) — this is why the next item became a held-out MARGINAL-recovery check, not a full joint-shape validation.

2. **"Scope and build the actual code change" — DONE, as `src/aim6_masev_tetraspanin_validation.py`.** Built, tested (TVD 0.011 PANC-1 / 0.019 CAPAN-2), and later extended in the same session with the ASPC1/A549 held-out prediction described in item 3.

3. **"Design the novel checkable prediction step" — DONE, via BOTH candidates named here, not just one.** (a) The held-out ASPC1/A549 marginal-recovery prediction (a correlation committed from PANC-1/CAPAN-2 training data only, applied unchanged to ASPC1/A549's real marginals) — recovery errors 0.03-0.26 percentage points. (b) A second, independent real-data check entirely: Aim 7, built from a different paper (the CRC plasma-exosome paper), checking whether a named cluster's cancer-enrichment replicates across two independent real patient cohorts — 2.08x enrichment, confirmed. Aim 6 and Aim 7 are different EVIDENCE TYPES (predictive validation vs. replication check) — see `EV-Capture-CURRENT.md`'s "Known risks" for why these must never be described with the same language.

4. **Option 3 (open-source toolkit) — still appropriately deferred, unchanged.**

5. **"SVAtlas's actual zip files were never opened" — RESOLVED, and this is the biggest surprise of the whole pivot.** A LATER session discovered SVAtlas has a second, separate raw-data download page (`https://www.svatlas.org/download.php`) that this scoping session never found (this session only ever used the JSON API endpoints, which return summary/metadata, not raw per-vesicle files). That download page has genuine per-vesicle CSV/Excel files under three categories (High-throughput Profiling, Body fluid, Disease). The user downloaded three of them directly in a browser (this environment's own sandboxed shell still cannot reach `raw.svatlas.org` — confirmed again, same allowlist block as before) and uploaded the results:
   - **PRJ20230304 (the SAME MASEV paper)** — turned out to be Figure 6A's raw per-vesicle data (3,000 real vesicles per cell line for PANC-1/CAPAN-2), NOT the same dataset as the Figure 4 percentages already validated against (a real, checked, and reported difference — up to 13.1 percentage points on some marginals; see `src/aim8_raw_vesicle_correlation_check.py`'s docstring for the full account of how this was verified against the paper's own text, including a self-caught mislabeling error along the way). This raw data let the project measure a REAL tetraspanin pairwise correlation for the first time (previously always a swept, assumed parameter): ~0.08-0.15, positive and significant, but genuinely lower than Aim 6's committed sweep value of 0.2.
   - **PRJ20230130 (the SAME CRC paper Aim 7 already used)** — real long-format proximity-barcoding data, 24,000 real vesicles across 8 real patient samples. Let the project measure a real ITGAM+/ITGAL+/ITGB2+ triple-positive fraction directly (0.5%, n=120) and compare it honestly to Aim 7's own published cluster11 percentage (4.58%) — a real, reported, non-flattering difference (different computation: simple threshold vs. the paper's own clustering algorithm). Also surfaced a genuinely new comparison (tumor location, colon vs. rectal) that no prior summary table reported — real, significant differences on all four markers, but explicitly NOT a healthy-vs-cancer comparison (this file has no healthy controls).
   - Both raw-data checks are now `src/aim8_raw_vesicle_correlation_check.py` (Parts A and B), fully tested (13 tests), passing.
   - **This raw-data page was the direct trigger for a full ISEF-competitiveness reassessment** (see `EV-Capture-CURRENT.md` for the verdict and the deepening ideas it produced) and for a further, broader search for similar raw single-vesicle repositories beyond SVAtlas — see that file's "What changed" history for the NanoFlow Repository and OMIX010139 findings that search turned up.
