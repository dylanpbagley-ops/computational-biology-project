Amended October 3, 2026, **before parsing any new marker-expression rows** from the selected GSE305971 pilot tables. Version 1 and its SHA-256 sidecar remain unchanged at `selected_protocol.md` and `selected_protocol.md.sha256`; v2 corrects cell-count eligibility, common threshold candidates/tie handling, and descriptive paired contrasts. One selected count table (GSM9189168/AB14564, putative code `tlv53`) had already been inspected during the earlier feasibility slice, including marker summaries. It remains excluded from all primary metrics. This protocol amendment was made before parsing the other 85 selected count tables.

This is a small feasibility and policy-comparison pilot, not an atlas-wide estimate, independent replication, target-discovery exercise, or clinical validation.

## Question and prior-art boundary

In a metadata-selected subset of the public GSE305971 MARS bone-marrow single-cell atlas, can a healthy-reference expression threshold fitted to a 10% normal-cell-positive budget produce a usable held-out-code comparison of malignant-cell coverage, and how do pooled, equal-code, and worst-training-code thresholds compare? This asks about an explicit cross-code threshold policy. It does not claim new selectivity for TNFRSF17, GPRC5D, or SLAMF7 and does not recreate the published patient-level z-score target ranking.

The closest published work already performs within-patient normal-versus-abnormal or normal-versus-malignant plasma-cell comparisons, including GSE193531 within-patient differential expression and GSE305971 per-patient malignant-versus-normal z-score target ranking. The paired mean and optional standardized contrast below are transparent descriptive comparators only; neither is an implementation or head-to-head replication of the published DE/z-score pipeline. Exact threshold values are fitted and evaluated within the MARS count assay and are never transferred from GSE193531. The candidate contribution is limited to the cross-code reference-budget policy comparison and its measured uncertainty; it is not a new biological target claim.

## Threshold candidates and held-out policy evaluation

The three fixed markers are TNFRSF17, GPRC5D, and SLAMF7. The primary positive budget is 10% of source-labelled Healthy/Normal_PC cells; 5%, 20%, and 50% are secondary budget sensitivities.

For each marker, training fold and budget, form one shared sorted threshold-candidate set for all policies: zero; every distinct normalized Healthy/Normal_PC training value; and `nextafter(value, +infinity)` for every such value. Positivity is `value >= threshold`, so ties count as positive. Choose the numerically lowest candidate meeting each policy's stated constraint. If the threshold is above the maximum training reference value, serialize it as `ABOVE_MAX` (not a zero or an invented finite expression level). Preserve exact round-trip decimal values for finite thresholds.

If at least four nonempty Healthy/Normal_PC and four nonempty MM/Malignant putative codes remain after the `tlv53` exposure exclusion, assign all such codes to four deterministic code-level folds with `numpy.random.default_rng(20261003)`: assign healthy codes from their sorted IDs, then assign MM codes from their sorted IDs using the same generator. Each code is held out once; all its GSMs, batches, cells, and tissues remain together. No marker values from the held-out code enter fitting. If fewer than four nonempty codes remain in either group, do not invent a cell-level split; retain all available code-level descriptive results and state that four-fold comparison is unavailable.

For each fold and budget, fit on healthy training codes only:

1. **Pooled:** lowest shared candidate whose pooled training-cell positive fraction is at most the budget.
2. **Equal-code:** lowest shared candidate whose mean training-code positive fraction is at most the budget.
3. **Donor envelope:** lowest shared candidate for which every training code's positive fraction is at most the budget; record the worst-code fraction at the selected cutoff.

Apply each locked threshold to held-out Healthy/Normal_PC and MM/Malignant cells. Report per-code and per-fold cell-weighted and equal-code fractions, code/cell denominators, threshold values, and held-out code-level spread (including each code's `1/n` fraction resolution). Do not use folds as independent replicates or calculate population confidence intervals, p-values, bootstrap cells, or claim equivalence. The pilot is small; uncertainty is represented by individual held-out code outcomes and fold-to-fold variation, not a population-level interval.

Repeat the policy evaluation as a separate sensitivity using only codes with at least 50 exact-joined cells in the relevant group, if four such codes exist per group. This screen cannot remove or invalidate any code from the primary descriptive analysis. The uncertain-label sensitivity refits healthy training thresholds after adding selected Healthy/Malignant-labelled cells as an explicitly uncertain reference component; it reports threshold change and held-out Healthy/Normal_PC, MM/Malignant, and uncertain-cell fractions, without reclassifying those cells.

## Paired within-code description

For every selected myeloma code with at least one finite exact-joined malignant cell and one finite exact-joined Normal_PC cell, report the descriptive paired mean difference (malignant minus Normal_PC), irrespective of a 50-cell threshold. A zero group mean does not make the mean difference undefined. Report cell counts and label standardized contrasts as undefined when the Normal_PC sample standard deviation is zero, nonfinite, or unavailable (fewer than two cells); never replace an undefined value with zero. The optional standardized contrast remains a simple descriptive comparator, not the paper's z-score, DE, or target-prioritization score. Provide a separate >=50-cell sensitivity label where applicable.

## Contribution gate and interpretation

The data-format gate passes only if the recorded files/hashes, count checks, and exact joins pass. The analysis-availability gate passes for four-fold results only if there are four or more nonempty codes per group; it does not imply adequate precision. Every conclusion must display exact numbers of codes/cells, per-code `1/n` resolution, fold-to-fold movement, and the sensitivity restriction. A small code denominator or a result whose direction changes with one held-out code is too uncertain for a strong extension claim.

The contribution gate is **not** passed merely because a script runs, known targets differ in average expression, or a patient-specific malignant-versus-normal contrast is observed. A follow-up within this same dataset is worth considering only if the primary all-nonempty-code analysis shows an interpretable held-out normal-budget/malignant-coverage tradeoff beyond the cited within-patient DE and per-patient z-score prioritization, the policy ordering is not dependent on a single code, and its direction is retained in the >=50-cell sensitivity. Report the counterevidence and code-level variation. Otherwise conclude that this pilot demonstrates no strong extension. A positive pilot signal would motivate a separately frozen larger within-study analysis; it would still not establish an independent cohort, generalizable threshold, therapeutic selectivity, protein abundance, patient harm, normal-tissue safety, or clinical utility. Cohort non-overlap with GSE193531 remains unverified because public participant identifiers cannot be crosswalked.
