**Version date:** 2026-10-03. **Lock timing:** after completion and review of the small pilot, but before downloading any of the 370 additional processed count tables or parsing their marker counts. This is a staged, post-pilot analysis plan, not pristine preregistration. The v2 pilot result and all prior exposure are disclosed below.

## Question and scope

Among source-annotated bone-marrow plasma-cell MARS profiles in GSE305971, how do three prespecified ways of fitting a shared RNA threshold to the same healthy reference budget differ in held-out-by-code healthy-cell positivity and MM malignant-cell positivity? This is an assay-level, within-GSE code generalization analysis. It does not test clinical sensitivity, tissue-wide safety, protein abundance, patient benefit, or independent replication.

The narrow candidate contribution is the empirical, code-held-out comparison of a pooled-cell budget, an equal-code mean budget, and a worst-code budget. It is not discovery of TNFRSF17, GPRC5D, or SLAMF7, nor generic target prioritization. The source publication already reports per-patient malignant-versus-Normal_PC z-score target ranking and includes these established targets among its results. Its exact z-score transform and reference pooling will not be claimed as reproduced: where useful, paired within-code mean differences are only a transparent descriptive comparator. Patient non-overlap with GSE193531 or any source cohort remains unverified.

## Exposure-aware primary and secondary analysis sets

**Primary newly examined codes:** fit each policy using only the eight fixed pilot Healthy/Normal_PC training codes, then evaluate on every exact-joined nonempty code among the nine new Healthy/Normal_PC and 90 new MM/Malignant codes. No 50-cell minimum is applied. Report a code with zero exact-joined cells as absent/empty, never as a zero positive fraction, and retain each nonempty code regardless of its cell count. Do not assign cells from one code to a different fold or split a code across training and test.

**Secondary full-frame code-CV:** use all 17 Healthy codes and all MM/Malignant codes except pre-exposed `tlv53` (105 total eligible MM codes); four deterministic code-level folds, using NumPy seed `20261003` and the v2 fold procedure. Every nonempty code is retained in the primary descriptive CV output; a >=50-cell screen is reported only as a sensitivity. This secondary result is explicitly exposure-influenced and cannot be called a fresh held-out validation. If either group has fewer than four nonempty codes after exact joining, report CV unavailable, with reason; do not imply sample sufficiency from row count.

**Uncertain-label sensitivity:** retain `Healthy/Malignant` source-label cells separately. Primary thresholds use Healthy/Normal_PC only. A locked sensitivity refits the same three threshold policies on the eight training Healthy/Normal_PC codes augmented with uncertain-label cells from those same codes, then reports new Healthy and new MM outcomes and the uncertain group separately. Do not reclassify these uncertain cells. Report counts and threshold changes; no decision-dependent retuning.

**Same-study prior-art comparator:** where both source-labeled MM/Malignant and MM/Normal_PC cells occur within a code, report paired differences in untransformed normalized marker means. A mean difference is defined for any two nonempty finite groups, including a zero mean; standardized contrasts are `NR` if the Normal_PC group has fewer than two cells or zero variance. This is not the paper's per-patient z-score workflow, not a discovery baseline, and not an independent cohort comparison.

## Values, policies, thresholds, and outcomes

Analyze integer gene-level molecule counts from each exact batch file. For each retained cell and target, calculate `10,000 * target_molecule_count / sum_of_all_gene_molecule_counts`. Do not use marker positivity to select samples, cells, batches, or codes. Primary targets are the fixed established genes TNFRSF17, GPRC5D, and SLAMF7.

For every marker and budget, use the same candidate set for all policies: zero, each unique Healthy training value, and the next representable floating-point value above each such value. A cell is positive when its normalized value is greater than or equal to the threshold. Select the lowest candidate meeting the prespecified constraint: pooled-cell mean positivity <= budget (`pooled`), unweighted mean of per-code positivity fractions <= budget (`equal_code`), or maximum per-code positivity <= budget (`donor_envelope`). Fit cutoffs only from the fixed training codes. Primary budget is 10%; 5%, 20%, and 50% are secondary. A cutoff above the maximum reference value may still detect positive MM cells and must retain its exact number plus a separate `ABOVE_MAX` state.

For each policy, marker, and budget, report the training constraint and its number of codes/cells; held-out Healthy and MM nonempty-code and cell denominators; positive counts; pooled-cell and equal-code positivity fractions; code-level range/median; each code's one-cell resolution; the number of held-out Healthy codes above the normal budget; and the number of MM codes above the corresponding illustrative fraction (not a normal-budget violation). Report exact numeric cutoff and state separately. Keep `NR`, empty, zero, and missing distinct. Do not calculate cell-level confidence intervals, infer population-level uncertainty from cells, tune on held-out values, test significance, or claim clinical safety/effectiveness.

The four-fold secondary CV reports code/fold variation, not a confidence interval. The >=50-cell analysis is only a resolution sensitivity; it cannot certify adequacy. No particular code-level outlier is dropped after inspecting values. Sensitivity analyses are reported alongside primary results, not substituted for them.

## Reproducibility, validation, and interpretation gate

Before parsing the additional tables, the runner must verify SHA-256 for the annotation workbook, GEO file index, source metadata candidate manifest, pilot selection manifest, exact full metadata manifest, exact file-size/download manifest, protocol files, and all downloaded tables. Each table must pass strict integer/nonnegative count parsing, integer-sum overflow validation, and exact keyed `(cell ID, Amp.Batch.ID)` annotation join. Reject malformed/fractional counts, duplicate selected cell IDs across count files, total zero counts, and any mismatched keyed cell instead of repairing it silently. Report every selected, exact-joined, unmatched, and excluded cell by group and file.

The result can support a **bounded computational extension** only if the primary new-code outcomes empirically show a nontrivial, reproducible normal-budget/marker-detection tradeoff not already conveyed by the source's patient-specific malignant-versus-Normal_PC ranking: report how often each policy exceeds the Healthy budget on new codes, its cell-weighted/equal-code Healthy positivity, and the full code distribution of MM marker positivity. A lower held-out Healthy fraction accompanied by lower MM positivity is a measured tradeoff, not policy superiority or clinical utility. If policies merely reproduce their mechanically expected ordering, effects vary sharply by code, code-level granularity dominates, or the result adds no defensible question beyond the source's patient-level ranking, conclude **no demonstrated strong extension**. Do not force a positive novelty decision. In every outcome, do not claim novel target discovery, an independent cohort, tissue-wide safety, or patient-level clinical validation.
