## The project in one sentence

Affinity capture of extracellular vesicles is **nonlinear** in per-vesicle receptor count, so achievable tumor-vs-normal selectivity is governed by the **overlap of two receptor distributions**, not by the fold-change of their means — which means the standard way the field picks capture targets can rank them incorrectly.

**Extracellular vesicles (EVs)** are particles roughly 30–150 nm across that cells release into biofluids, carrying proteins from their parent cell on their surface. "Affinity capture" means coating a surface with molecules that grab those proteins, to pull tumor EVs out of a blood sample — the basis of a liquid-biopsy cancer diagnostic.

## What changed since v8 — READ THIS FIRST

**Context:** this transition happened in a review/discussion chat with the user, not a Cowork build session. No model code was changed. The user pushed back on v8's headline negative finding (see below) before accepting it, asked for the underlying assumptions to be pressure-tested, and the codebase was uploaded into the chat so the actual functions could be re-run directly rather than reasoned about secondhand. **1. v8's headline claim — "genuine superselectivity (α>1) is not reached anywhere in the numerically-reliable plausibility grid" — DOES NOT REPRODUCE, and the reason is a confirmed, specific bug.**

`src/aim3_aim4_range_sweep.py`'s `sweep_superselectivity_reachability()` is defined as:

```python
def sweep_superselectivity_reachability(sigma=1.0, n_max=200):
```

The default value of `sigma` is `1.0` — the OLD placeholder value used throughout the project's earliest demo scripts, not `SIGMA_LOPEZ_BALTAZAR_ABS_PER_CM2` (4.44×10¹¹ Abs/cm²), the real antibody surface density that every K_INTRA value in the sweep's own grid was derived against (via `k_intra_bounds_from_real_sigma()`). The function is called with **no arguments** at its one call site (inside `print_summary()`), so it silently runs with `sigma=1.0` in production, not the real sigma.

This is the exact same class of error the v8 handoff itself documents catching and fixing as "Bug 1" in `sweep_ranking_flip_robustness()` (pairing new real-σ-derived K_INTRA values with the old placeholder σ=1.0, which silently shrinks the effective exponent by a factor of ~4.4×10¹¹). **That fix was applied to the ranking-flip function but never applied to the superselectivity-reachability function**, which still has the bug live in its default arguments.

Numerically confirmed in the review chat, calling the function both ways with everything else identical:

| Call | max_alpha_found | any_superselective | fraction_of_grid_superselective | grid_size (reliable cells) |
|---|---|---|---|---|
| `sweep_superselectivity_reachability()` — as actually called in the script (sigma defaults to 1.0) | 1.000013 | False | 0.0 | 13 (91 excluded as numerically unreliable) |
| `sweep_superselectivity_reachability(sigma=SIGMA_LOPEZ_BALTAZAR_ABS_PER_CM2)` — same K_INTRA/z grid, correct sigma | **10.46** | **True** | **0.596** | 104 (0 excluded) |

With the bug present, the wrong (far too small) sigma makes `n*sigma*K_INTRA` land near float64 machine epsilon for most grid cells, which is why 91 of 104 cells were excluded as "numerically unreliable" — the sweep was only ever really testing 13 of its 104 intended (K_INTRA, z) combinations. With the correct sigma, no cells need to be excluded, and roughly 60% of the grid shows a real, reliable α>1 signal, peaking around α≈10.46.

**This means v8's stated "Known risks" entry — "the model's current plausibility bounds do not reach genuine superselectivity (alpha>1) anywhere" — is not currently a valid finding.** It was produced by a bug, not by real physics. The correct, currently-best-available answer is the opposite: superselectivity IS reachable across a majority of the current plausibility grid, once the sweep is run the way it was designed to be run.

**2. A second, related concern was raised and partially — but not fully — investigated: whether the plausibility bounds' own `target_exponents=(0.01, 0.1, 1.0)` ceiling is itself too conservative, independent of the sigma bug above.**

`k_intra_z_plausibility_bounds.py`'s bounding argument caps the dimensionless exponent `n*sigma*K_INTRA` at a target between 0.01 and 1.0, reasoning (module docstring, point 2) that real single-marker capture assays are not deep in the saturated regime (theta ~ 1), so the exponent should stay in that range for typical n (1–100).

This conflates two different constraints: **theta staying below 1** (well-supported, real) and **the exponent n·σ·K_INTRA staying below 1** (not the same claim). `z` sits outside the exponential in `theta = z*q_b/(1+z*q_b)` and can keep theta arbitrarily far from saturation at ANY exponent value, simply by being small enough — confirmed numerically in the review chat (e.g., exponent=5, z=0.001 gives theta≈0.13, nowhere near saturated). The bounds file's own `selectivity_alpha()` docstring already documents a real α≈6 example at sigma=1.0, k_intra=0.2, z=1e-4 — an exponent of up to ~20 at n=100 — which is far outside the (0.01–1.0) target-exponent ceiling the plausibility file actually sweeps.

**This was NOT resolved in the review chat** — it's flagged here as a second, independent, currently-open question, separate from and in addition to the sigma bug in item 1. Fixing item 1's bug alone (which uses K_INTRA values still derived under this same 0.01–1.0 ceiling) is what already produces the α≈10.46 finding above; item 2 asks whether the ceiling itself should be widened further, which could push the reachable-α findings even higher, or reveal additional structure (e.g., an optimal intermediate exponent, matching the classic superselectivity shape) that the current narrow grid can't see. Worth investigating as a next step, not urgent to resolve before fixing item 1's clear bug.

**3. What this does NOT change:** `sweep_ranking_flip_robustness()` was not touched in the review chat and was not re-verified beyond what v8 already reports. Its "Bug 1" fix (real sigma correctly threaded through) appears, from reading the code, to already use `SIGMA_LOPEZ_BALTAZAR_ABS_PER_CM2` as its default (`def sweep_ranking_flip_robustness(sigma=SIGMA_LOPEZ_BALTAZAR_ABS_PER_CM2, z=1.0)`), unlike the superselectivity function — but this should be independently re-confirmed as part of the fix-and-rerun work below, not assumed correct by analogy. The ranking-flip finding (healthy/PDAC-plasma flip is robust; PANC-1/HPDEC does not show the same flip) should be treated as provisionally still valid, but re-run alongside the superselectivity fix as a matter of due diligence, given that a same-class bug just turned up in the sibling function.

**4. Practical note on how this was found, worth repeating for future sessions:** the bug was caught by physically re-deriving what the sweep's own numbers implied (checking that the max K_INTRA value actually tested, combined with real n from the digitized data, produced a far larger exponent than the sweep's own docstring claimed to be testing), then directly re-running `sweep_superselectivity_reachability()` with its default arguments vs. with the sigma explicitly corrected, and comparing outputs — not by re-reading the code more carefully or re-deriving the physics from scratch. This is the same "inspect the raw numbers, don't trust the summary statistic" discipline v8 itself used to catch its first two bugs, now shown to need applying one level deeper: to the function signatures and call sites themselves, not just the numerical output of a single believed-correct run.

## What changed since v7

This session picked up v7's single top-priority item — retry retrieving the Lopez Baltazar PhD dissertation, whose full text v7 had located but could not download due to a tool limitation (no working browser, and a large-file fetch that returned empty/error responses). This time, Claude-in-Chrome (the browser tool) was connected, and the retrieval succeeded. What followed was a careful, multi-step piece of real reasoning — not just "problem solved" — so it's worth walking through in full.

**1. The dissertation was retrieved, and it contained exactly the number v7 said was missing.** v7's plausibility-bounds file said, verbatim: the Kd=1.92nM number is usable, but "the actual antibody surface density in physical units (molecules/um², not just '40% coverage of an unspecified maximum')... could NOT be recovered." This session found it: Appendix A.1 of the dissertation ("Antibody Surface Coverage Estimation," p.136) works out, from real antibody physical dimensions, that the SPR chip's maximum close-packed antibody density is **1.11×10¹² antibodies/cm²**. The "40% surface coverage" condition that produced the headline Kd=1.92nM therefore corresponds to a real, physical **σ = 4.44×10¹¹ antibodies/cm²** (also independently stated in the text as 104 ng/cm², which matches). This closes the specific, narrow gap v7 identified.

**2. Getting this number required solving a real retrieval problem, worth recording for future reference.** The dissertation is a 192-page, 11.2 MB PDF. Chrome's native handling of the PDF triggered a background *file download* rather than opening it as a viewable page — so standard navigation and text-extraction tools saw only a `chrome://newtab/` redirect, not the document. The fix: proxy the PDF through Google's public document viewer (`https://docs.google.com/viewer?url=<encoded PDF URL>&embedded=true`), which renders the PDF inline as a scrollable web page that Chrome's page-reading tools CAN see. Within that viewer, page-by-page navigation via scrolling was very slow (the viewer lazy-renders a few pages at a time and a raw scroll only advances ~1 page per resolved tick); jumping via the viewer's own page-number input box was far faster and got to the right section (Appendix A.1) directly. This is a reusable technique for any future large academic-PDF retrieval this project needs.

**3. Careful, honest reasoning was required to determine whether this number actually unlocks a K_INTRA calibration — and it does not, for a specific, checkable reason, distinct from why it didn't work in v7.** This was worked out explicitly, not assumed either way:
   - The model's `K_INTRA` is a *2D areal* binding-strength parameter (units: 1/(receptor count × ligand density)) — it describes how strongly one receptor and one ligand bind when both are sitting on/near a surface.
   - The dissertation's Kd=1.92nM, despite coming from a genuinely surface-immobilized (SPR) experiment (the correct physical *regime*, unlike the previously-rejected solution-phase FIDA data), is actually a **3D bulk EV concentration** — the concentration of EVs in the flowing sample solution at which surface capture reaches half-maximum. It was measured across the natural, uncontrolled RAW 264.7 EV population (i.e., an unknown, ensemble-averaged CD81 copy-number distribution, not a single controlled n), and it folds in mass-transport/diffusion effects to the sensor surface.
   - This project's own `z` parameter in `binding_model.py` is explicitly defined to absorb exactly this kind of thing ("everything about vesicle concentration, incubation time, and transport to the surface that is NOT part of the multivalent bond-counting itself" — direct quote from that file's docstring, unchanged since earlier sessions). So Kd=1.92nM properly calibrates the **z / concentration axis**, not K_INTRA directly.
   - Converting a 3D bulk Kd into a 2D areal K_INTRA would still require an encounter-volume/contact-geometry model for EVs that doesn't exist — the same missing piece the plausibility file already documented for K_INTRA generally.
   - This was checked numerically, not just argued qualitatively (see the worked calculation and the file's updated docstring for the exact numbers).

**4. What this session's retrieval DOES concretely improve, honestly stated:**
   - **σ is no longer a mystery number for this specific source.** `k_intra_z_plausibility_bounds.py`'s dimensionless bound (n·σ·K_INTRA = target, for assumed n and target-saturation values) can now be divided through by a REAL σ instead of left as a bare per-receptor product — producing, for the first time, an actual K_INTRA range in physical units (cm²/antibody). New function: `k_intra_bounds_from_real_sigma()`. This is still not a fit (same ~4-order-of-magnitude width as before, since n and target are still assumed ranges) — but it's now anchored to something real rather than left dimensionless.
   - **The concentration-axis convergence finding is strengthened.** The dissertation's own linear dynamic range (1.9×10⁸–1.9×10⁹ EVs/mL, already known) plus newly-recovered control-experiment concentrations (4.9×10⁹, 5.9×10⁹, 1.9×10¹⁰ EVs/mL, from Appendix A's nonspecific-binding controls) extend the previously-known cross-platform convergence (Mizenko's dilution range, Kakavoulia's FIDA EC50s) upward by roughly one order of magnitude, to a combined ~10⁸–10¹⁰ particles/mL band spanning three independent papers/platforms.
   - **K_INTRA, z, and k_geom remain formally uncalibrated placeholders in `binding_model.py`** — unchanged in that specific sense. This session tightened the *units and confidence* of the bound, not its fundamental status as a bound rather than a fit.

**5. v7's queued next step — the Aim 3/4 range sweep — was run this session, and it caught two of its own bugs before reporting real findings.** Rather than accept the first version's output at face value, each surprising result was checked directly:
   - **Bug 1 (unit mismatch, caught before any conclusion was drawn):** an early version of the sweep paired the new real-σ-derived K_INTRA values with the *old placeholder* σ=1.0 (used throughout the project's earlier demo scripts), rather than the real σ they were actually derived against. Since K_INTRA = target/(n×σ_real), plugging it back in with σ=1.0 silently shrinks the effective exponent by a factor of ~4.4×10¹¹ — pushing every test deep into a numerically degenerate regime. Caught by checking that `n×σ_real×K_INTRA` recovered the intended target exactly, and that it did NOT when σ=1.0 was used instead. Fixed by defaulting the sweep to the real σ.
   - **Bug 2 (floating-point artifact, caught by noticing non-physical output):** even after fixing bug 1, the smallest K_INTRA values in the plausibility range produce an exponent (n×σ×K_INTRA at n=1) at or below float64 machine epsilon, causing `exp(x)-1` to lose precision catastrophically. This produced *wildly oscillating* alpha values (jumping between ~0.87 and ~1.21 between adjacent, nearby n values, rather than tracing a smooth curve) — caught by printing the raw alpha array and noticing it wasn't smooth, not by trusting the summary statistic. Fixed by excluding grid cells below a reliability floor and reporting the exclusion explicitly rather than silently.
   - **After both fixes, the real, honest findings are:**
     - The healthy/PDAC-plasma (size-mismatched) ranking flip from v4 is **robust across the entire plausibility range** — ratio_p2>1 and ratio_p0<1 hold at all 8 distinct K_INTRA values tested, spanning 4 orders of magnitude. This is a genuine strengthening of the v4 finding.
     - The PANC-1/HPDEC (roughly size-matched) comparison does **not** show the same kind of flip, but the picture is more nuanced than v7's "does not flip" framing: ratios stay close to 1 (0.99–1.48) across most of the range, dipping slightly *below* 1 only at the single largest, most-saturating K_INTRA value tested (ratio_p2 = 0.9995 there). This was checked directly to confirm it's real (yields there are mid-range, 0.55–0.59, nowhere near float-precision limits) and physically sensible (as both populations approach saturation, small differences between similarly-sized populations shrink and can tip either way) — not evidence the original v4 finding was wrong, but a reason to state it as "does not show a large flip, except within a hair's breadth of full saturation" rather than an unconditional rule.
     - **Alpha>1 (genuine superselectivity) is NOT reached anywhere in the numerically-reliable portion of the swept (K_INTRA, z) grid.** The entire plausibility range keeps the model deep in the dilute/linear Langmuir regime (alpha stays within numerical noise of exactly 1.0, max reliable value found: 1.000026, well under a 1% threshold used to distinguish a real signal from float noise). This is a real, negative, and useful Aim 4 finding: with parameters as currently bounded, the model does not predict genuine superselective behavior for realistic single-marker EV capture — reaching alpha>1 would require either K_INTRA outside the current plausibility bounds, or revisiting whether the bounds themselves (built from real Kd anchors) are set correctly.
   - New file: `src/aim3_aim4_range_sweep.py`. New tests: `tests/test_aim3_aim4_range_sweep.py` (5 tests, all passing, specifically written to lock in the corrected findings and guard against either bug regressing).

Both headline reproduction numbers (1.69 SE for analytical-vs-Monte-Carlo agreement; 28.1% relative yield difference for the Poisson-vs-negative-binomial population demo) were re-run and reproduce exactly, confirming nothing was silently broken by this session's changes.

## Three physical mechanisms the model must include

Unchanged this session. Preserved in full from v4/v5/v6/v7:

A naive calculation says capture shouldn't work: a vesicle is a sphere touching a flat surface, so only ~3% of its surface is in the contact patch, giving well under one receptor in contact. But capture demonstrably works. Three mechanisms resolve this, and **all three are real and they interact**:

**(a) Lateral diffusion / receptor recruitment.** EV membranes are fluid, so receptors drift into the contact zone after the vesicle settles. Jahnke et al. 2024 (*J Extracell Vesicles*, DOI 10.1002/jev2.12436) calculate this takes about a second or less for a 100 nm vesicle. Real capture runs 15 minutes to overnight — 10³ to 10⁵ times longer than needed. The static 3% snapshot is the wrong quantity. Independent confirmation from virology (Brownian Adhesive Dynamics, PMC1305223): binding is much greater when receptors can diffuse into the contact zone than when held fixed. **Models that hold receptors still systematically underpredict capture.**

**(b) Vesicle deformation.** Vesicles are soft and flatten on contact. Jahnke et al.: a vesicle engaging 5–50 bonds at ~4 k_BT each, against a bending rigidity of 20–30 k_BT, means a few bonds already deform it. **This is a feedback loop** — bonds form → vesicle flattens → patch grows → more receptors fit → more bonds. **This mechanism is the explicit basis of the resolved n-vs-areal-density question** (see Aim 1): the same low bending rigidity that makes this feedback loop possible is also the physical reason the model's default treats contact-patch area as scaling with diameter² (soft-adhesion/"liquid" contact-mechanics limit for small, floppy bodies).

**(c) Ligand grip strength.** Antibodies bind roughly 1000× more tightly than RGD peptide (nanomolar vs. micromolar Kd, measured head-to-head, *Anal. Chem.* DOI 10.1021/acs.analchem.7b00554). Working capture devices all use antibodies. Reference values: linear RGD binds αvβ3 at ~89 nM; heptapeptide GRGDSPK at ~12.2 nM (*Biophys Rev* DOI 10.1007/s12551-023-01084-3).

**(d) Accessibility / protein corona.** EVs in biofluids acquire an adsorbed plasma-protein layer that occludes surface epitopes. Implement as a single multiplier `f_accessible` on `n`, not as a mechanistic corona model. If `f_accessible` differs between tumor and normal EVs — plausible, since corona composition depends on surface charge and lipid composition — it contaminates the selectivity ratio, which was supposed to be robust because errors cancel. Carry it as an uncertainty and test sensitivity. Source: Försönits et al. 2025, *J Extracell Vesicles*, DOI 10.1002/jev2.70124.

**A testable prediction falls out of (a):** incubation time is a selectivity knob nobody is turning. Short incubation → no time to reshuffle → only richly decorated vesicles stick → selective, low yield. Long incubation → sparse vesicles gather enough bonds → high yield, worse selectivity. Mapping this trade-off appears to be novel.

## My prior result (preserve this — it's the logical spine)

I proved that **for Poisson-distributed receptors, mean-field theory is exact** (exactly, at the `q_b` partition-function level; approximately, within 1–5%, after the Langmuir conversion). ## Key literature

**The anchor paper — Mizenko et al. 2021**, *J Nanobiotechnology* 19:250, DOI 10.1186/s12951-021-00987-1. Open access, ~171 citations.

They measured experimentally that capturing EVs by a single surface protein biases which tumor markers you find — roughly tenfold fewer EpCAM-positive and fivefold fewer Her2-positive vesicles via single-tetraspanin capture versus non-specific capture. Their interpretation is my thesis, stated by them: a large fraction of non-tetraspanin-expressing vesicles may carry the bulk of these markers. Their recommendation is my multi-marker idea: study multiplexing efficiency before choosing a single capture protein.

**Precise methodology, confirmed by reading the paper's actual methods section (unchanged since v6/v7).** Single-tetraspanin capture uses antibody-coated chips (anti-CD9, anti-CD63, anti-CD81) that bind EVs bearing that specific tetraspanin. Non-specific capture uses a genuinely different mechanism: EVs are first chemically biotinylated at any exposed surface amine group (independent of which proteins are present), then captured on an anti-biotin-coated chip — a near-total, marker-independent capture of the population. Both captured populations are then stained with anti-CD24/anti-EpCAM/anti-Her2 detection antibodies. The reported 10×/5× numbers are the ratio of EpCAM+/Her2+ counts between these two captured populations — i.e., **a co-occurrence measurement between tetraspanin status and tumor-marker status, not a capture-efficiency measurement for any single marker's own ligand-receptor pair.** Direct quotes: "Although EpCAM + EVs could be detected on all three tetraspanin capture spots at similar rates, biotin capture identified more EVs by approximately a tenfold difference. Her2 + EVs were identified with high frequency on all tetraspanin spots with approximately 5 times as many detected on the anti-biotin capture spot." And: "there may be a large percentage of non-tetraspanin expressing EVs that contain the bulk of these markers." Sample: SK-OV-3 (ovarian cancer cell line) EVs, N=3 capture spots per condition, ExoView/SP-IRIS platform.

**Cite prominently as motivation.** What they did NOT do, and what remains mine:
- No theory — they report 10×, can't explain *why* 10× rather than 3× or 50×, can't predict for untested proteins
- No prediction — every new protein/cell line/surface needs a new experiment
- No quantified trade-off — "use a combination" without saying which or at what yield cost
- Only three proteins on one cell line

Framing: *the bias is known and measured — here is the physical theory that explains its magnitude, predicts it for untested proteins, and quantifies the yield cost of the fix everyone recommends but nobody has sized.* **Explaining a known phenomenon is safer than discovering a new one** — it hands you real numbers to validate against. **This framing applies specifically to Aim 3b (the co-occurrence/independence model), not to a single-marker K_INTRA/z/k_geom calibration.**

**The nanostar validation paper: Linne, Heemskerk, Zwanikken, Kraft & Laan 2024**, *Soft Matter* 20:8515-8523, DOI 10.1039/d4sm00704b, PMC11484159. Open access.

DNA-origami nanostars with a fixed number of branched arms (valency `k`), each with a single-stranded "sticky end" that binds a complementary receptor on a supported lipid bilayer, imaged by TIRFM. Measured bound fraction Y as a function of receptor density σ_R, for k=1,3,4,10 (main valency sweep) and for three different sticky-end binding strengths at fixed k=6. Key findings, all directly relevant to this project's theoretical foundation:
- Selectivity α = d ln(Y)/d ln(σ_R) peaks at an *intermediate* valency, k=3 — not the largest valency tested (k=10). This is the headline external signature this project's Aim 2 leg 3 aimed to reproduce.
- The paper's SIMPLE independent-arms model (their Eq. 3-4, treating ligands as acting independently) does **not**, on its own, explain this k=3 optimum when fit to the real data — fitting it requires a different K_intra for each valency, which the paper itself calls "puzzling" and describes as evidence the simple model is "incomplete" or "inconsistent." Their real explanation is a second, extended model incorporating ligand-ligand pair interactions (cooperativity/competition), represented by a free energy term ΔG_c, fit via kinetic Monte Carlo (Gillespie algorithm) simulation — NOT the closed-form equations. ΔG_c becomes more *competitive* (arms interfering with each other) as valency increases: fitted values ΔG_c = −0.5, 0, +1.0 k_BT for k=3, 6, 10, with a SHARED K_intra=14×10⁻¹² and K_A=1×10⁻⁵ M⁻¹ across all three valencies (published Table 2).
- Binding strength also has an optimum (their k=6 sweep): too strong and the transition happens at too-low receptor density to resolve; too weak and multivalent effects wash out.
- **This project's reproduction (`src/nanostar_validation.py`) implements ONLY the simple independent-arms equations (Eq. 2-4), with representative per-k K_intra values chosen to decrease with k** — a mechanism the paper's own text indicates is NOT the real explanation for their data. This should be described as "a demonstration that the simple model's functional FORM can produce a qualitative k=3 optimum for some parameter choice," not as a faithful reproduction of the paper's own mechanism (unchanged since v6/v7).
- Their exact fitted numeric values for the SIMPLE model (Figure 2(e)'s table) remain unrecoverable as text (checked across PMC, RSC, and arXiv — all three embed this specific table as a graphic). The arXiv preprint (arXiv:2306.16885) is an earlier draft with DIFFERENT numbers (ΔG⁰=−7 kT vs. the published −8.4 kT) — do not mix numbers between versions.
- **A concrete, well-specified path to a tighter reproduction still exists, not attempted this session either:** implement the Gillespie kinetic Monte Carlo simulation described in the paper's Methods, using the published Table 2 values directly.

## Scope: what this project does and doesn't claim

Unchanged this session. Preserved in full from v4/v5/v6/v7:

The project shifted from engineering (*build a thing that works*) to science (*determine what's possible and how to choose well*).

- **The model predicts both yield and selectivity** — same calculation. But **selectivity is the more trustworthy output** because it's a ratio: uncertainties in ligand density, contact area, incubation conditions, and detection efficiency affect tumor and normal predictions the same way and partially cancel.
- **The real deliverable is the trade-off curve**, not a single optimum. Few ligands → low yield, good selectivity. Many ligands → high yield, poor selectivity. The curve also shows which combinations are *physically impossible* regardless of engineering.
- **Relevance is asymmetric, state it honestly:** high specificity matters most for *diagnostics* (tumor EVs are a tiny minority in blood; low yield is fixable by running more sample, poor specificity isn't). For *therapeutic* filtering, yield matters much more.
- **Hard ceiling worth remembering:** if only 20% of vesicles carry a target, yield can never exceed 20%. Bulk measurements cannot see this.
- **A transferable idea worth developing:** a *computational* limit of detection. Given measured distributions, what is the minimum tumor-EV fraction that any affinity surface could detect?

**The decomposition that matters most.** Published copy numbers average over all vesicles including zeros, blending two different quantities:

> **copies per carrier = overall average ÷ fraction carrying**

Worked example (positivity fractions estimated — illustrative, not publishable): CD9 17.0 ÷ ~0.33 ≈ 52. CD81 1.6 ÷ ~0.10 ≈ 16. A tenfold apparent gap collapses to threefold.

**This decomposition has been run on the real digitized Lennon matched pair** — see "The decomposition" above for the full result. Unchanged this session.

- **NEW practical/technical note for future sessions — the PDF-retrieval technique that worked:** when Chrome's native PDF handling triggers a background file download instead of an inline viewable page (which blocks page-reading tools since they see a `chrome://newtab/` redirect, not the document), proxy the PDF through Google's public document viewer: navigate to `https://docs.google.com/viewer?url=<URL-encoded PDF link>&embedded=true`. This renders the PDF as a scrollable web page that page-reading tools CAN see. Within that viewer, scrolling to advance pages is slow and lazy-loads only a few pages ahead at a time; using the viewer's own page-number input box (visible in a screenshot, typically near the bottom of the viewport) to jump directly to a target page number is much faster once you know roughly which page you need (e.g., from a table of contents rendered on an earlier page). This is a general technique, not specific to this dissertation — worth trying first for any future large academic PDF that a direct fetch or `chrome://` navigation can't reach.
