## The project in one sentence

Affinity capture of extracellular vesicles is **nonlinear** in per-vesicle receptor count, so achievable tumor-vs-normal selectivity is governed by the **overlap of two receptor distributions**, not by the fold-change of their means — which means the standard way the field picks capture targets can rank them incorrectly.

**Extracellular vesicles (EVs)** are particles roughly 30–150 nm across that cells release into biofluids, carrying proteins from their parent cell on their surface. "Affinity capture" means coating a surface with molecules that grab those proteins, to pull tumor EVs out of a blood sample — the basis of a liquid-biopsy cancer diagnostic.

**A real numerical subtlety was found and worked through while writing these tests, worth carrying forward.** An initial version of the identifiability tests checked for exact bit-for-bit equality (`np.array_equal`) between rescaled and baseline outputs, and this failed at a large rescaling factor (1000x) with an apparent difference of ~2×10⁴⁴ — which looked like a real violation of the identifiability property but was not. Investigated directly rather than just loosening the tolerance blindly: the exponent `x = n*sigma*k_intra` itself differs between the two rescaled versions by only a tiny floating-point rounding error (order 1e-16, invisible when printing `x`), but `q_bound = exp(x) - 1` is exponentially sensitive to `x`, so at `x≈133` (where `exp(x)≈7×10^57`), that tiny relative error in `x` becomes a huge absolute error in `exp(x)`. The fix: compare in log-space (`log(q_bound+1)`, which recovers `x` itself and is linear, not exponential) rather than comparing `q_bound` directly — this is the numerically correct way to check equality of a quantity spanning many orders of magnitude, and is the same general lesson `aim3_aim4_range_sweep.py`'s own `MIN_RELIABLE_EXPONENT_AT_N1` already encodes for a related (opposite-direction) reason. Documented in both the limitations doc and the test file itself so a future session doesn't have to rediscover this.

**6. A real numerical bug was found and fixed while building this file — caught before being reported, exactly the discipline this project has repeatedly needed and repeatedly found effective.** `population_model.joint_population_yield()` (the existing, validated, shared function used by the Lennon range sweep) computes `theta` via a direct `exp()` call inside `binding_model.q_bound()` with no overflow guard. This has never been a problem for the real digitized Lennon data, because its largest receptor counts (a few hundred at most) never push `n*sigma*K_INTRA` anywhere near float64's `exp()` overflow point (~709) even at the largest swept K_INTRA. **This file's reconstructed populations are different**: a negative binomial fit tight enough to match a strongly zero-inflated positivity fraction (e.g., CD73's 75% zero-fraction) necessarily has a heavy right tail, and checked directly, roughly 0.1-0.4% of a 5,000-vesicle reconstructed sample lands above the project's own previously-stated physical sanity bound (~500 copies for a ~100nm EV — see "Data situation"). At the single largest K_INTRA in the real-sigma plausibility range, a handful of these heavy-tail vesicles pushed `n*sigma*K_INTRA` past 900 — well over the overflow point — producing `inf` inside `q_bound`, then `nan` after the Langmuir division, which then **silently poisoned the entire population-average yield via `np.mean()`**. Because a `nan` does not raise an error when it reaches Python's `sorted()` (NaN comparisons are always `False`, so `sorted()` returns an arbitrary, meaningless order rather than crashing), an early version of this file's output printed a plausible-LOOKING ranking at the largest K_INTRA that was, on direct inspection, computed entirely from `nan` yields. **This was caught by explicitly checking a yield value directly rather than trusting the printed ranking** — the same "inspect the raw numbers, don't trust the summary" discipline this project's own "Practical notes" repeatedly credits for catching v7→v8's two bugs and v8→v9's third one, now caught a fourth time, in a new file, before anything wrong was ever reported as a finding.

   **The fix:** a new function, `stable_joint_population_yield()`, reimplements the identical physics (`q_b = exp(x) - 1`, `theta = z*q_b/(1+z*q_b)`) but takes the correct physical limit (`theta → 1`, certain capture) directly for any exponent large enough to overflow, rather than computing it via a literal `exp()` call that fails at large arguments. This is not a new modeling assumption — theta approaching 1 as the bond-count partition function diverges is already exactly what the exact, non-overflowing formula predicts; the new function just computes that limit correctly instead of via a code path that fails. **This was deliberately built as a new, local function in the new file, not as an edit to `binding_model.py` or `population_model.py`** — those are shared, validated, extensively-tested files used by every other part of this project, and changing their core numerics is a decision that deserves its own separate review, not a side effect of building one literature-table extension. A dedicated test (`test_stable_yield_matches_original_where_original_does_not_overflow`) confirms the new function agrees with the original to floating-point precision everywhere the original does not overflow, and another (`test_stable_yield_never_returns_nan_across_full_plausibility_range`) confirms no non-finite value ever reaches a ranking comparison again, across the entire real-sigma K_INTRA plausibility range, for every one of the nine reconstructed populations.

## Three physical mechanisms the model must include

Unchanged this session. Preserved in full from v4 through v10:

A naive calculation says capture shouldn't work: a vesicle is a sphere touching a flat surface, so only ~3% of its surface is in the contact patch, giving well under one receptor in contact. But capture demonstrably works. Three mechanisms resolve this, and **all three are real and they interact**:

**(a) Lateral diffusion / receptor recruitment.** EV membranes are fluid, so receptors drift into the contact zone after the vesicle settles. Jahnke et al. 2024 (*J Extracell Vesicles*, DOI 10.1002/jev2.12436) calculate this takes about a second or less for a 100 nm vesicle. Real capture runs 15 minutes to overnight — 10³ to 10⁵ times longer than needed. The static 3% snapshot is the wrong quantity. Independent confirmation from virology (Brownian Adhesive Dynamics, PMC1305223): binding is much greater when receptors can diffuse into the contact zone than when held fixed. **Models that hold receptors still systematically underpredict capture.**

**(b) Vesicle deformation.** Vesicles are soft and flatten on contact. Jahnke et al.: a vesicle engaging 5–50 bonds at ~4 k_BT each, against a bending rigidity of 20–30 k_BT, means a few bonds already deform it. **This is a feedback loop** — bonds form → vesicle flattens → patch grows → more receptors fit → more bonds. **This mechanism is the explicit basis of the resolved n-vs-areal-density question** (see Aim 1): the same low bending rigidity that makes this feedback loop possible is also the physical reason the model's default treats contact-patch area as scaling with diameter² (soft-adhesion/"liquid" contact-mechanics limit for small, floppy bodies).

**(c) Ligand grip strength.** Antibodies bind roughly 1000× more tightly than RGD peptide (nanomolar vs. micromolar Kd, measured head-to-head, *Anal. Chem.* DOI 10.1021/acs.analchem.7b00554). Working capture devices all use antibodies. Reference values: linear RGD binds αvβ3 at ~89 nM; heptapeptide GRGDSPK at ~12.2 nM (*Biophys Rev* DOI 10.1007/s12551-023-01084-3).

**(d) Accessibility / protein corona.** EVs in biofluids acquire an adsorbed plasma-protein layer that occludes surface epitopes. Implement as a single multiplier `f_accessible` on `n`, not as a mechanistic corona model. If `f_accessible` differs between tumor and normal EVs — plausible, since corona composition depends on surface charge and lipid composition — it contaminates the selectivity ratio, which was supposed to be robust because errors cancel. Carry it as an uncertainty and test sensitivity. Source: Försönits et al. 2025, *J Extracell Vesicles*, DOI 10.1002/jev2.70124.

**A testable prediction falls out of (a):** incubation time is a selectivity knob nobody is turning. Short incubation → no time to reshuffle → only richly decorated vesicles stick → selective, low yield. Long incubation → sparse vesicles gather enough bonds → high yield, worse selectivity. Mapping this trade-off appears to be novel.

I proved that **for Poisson-distributed receptors, mean-field theory is exact** (exactly, at the `q_b` partition-function level; approximately, within 1–5%, after the Langmuir conversion). Restated: *if* receptor counts were Poisson, the mean would be sufficient and fold-change ranking would be correct.

Real EV distributions are measurably **not** Poisson — zero-inflated and overdispersed (over half of vesicles carry none of the standard markers).

Argument structure:
1. Under Poisson, fold-change ranking is provably correct — **my result, the null model**
2. Real distributions are non-Poisson — **literature**
3. Therefore fold-change ranking has a quantifiable error — **my contribution**
4. Here is the corrected method and how much the ranking changes — **my result**

Step 1 doubles as a unit test.

## Key literature

**The anchor paper — Mizenko et al. 2021**, *J Nanobiotechnology* 19:250, DOI 10.1186/s12951-021-00987-1. Open access, ~171 citations.

They measured experimentally that capturing EVs by a single surface protein biases which tumor markers you find — roughly tenfold fewer EpCAM-positive and fivefold fewer Her2-positive vesicles via single-tetraspanin capture versus non-specific capture. Their interpretation is my thesis, stated by them: a large fraction of non-tetraspanin-expressing vesicles may carry the bulk of these markers. Their recommendation is my multi-marker idea: study multiplexing efficiency before choosing a single capture protein.

**Precise methodology, confirmed by reading the paper's actual methods section (unchanged since v6/v7).** Single-tetraspanin capture uses antibody-coated chips (anti-CD9, anti-CD63, anti-CD81) that bind EVs bearing that specific tetraspanin. Non-specific capture uses a genuinely different mechanism: EVs are first chemically biotinylated at any exposed surface amine group (independent of which proteins are present), then captured on an anti-biotin-coated chip — a near-total, marker-independent capture of the population. Both captured populations are then stained with anti-CD24/anti-EpCAM/anti-Her2 detection antibodies. The reported 10×/5× numbers are the ratio of EpCAM+/Her2+ counts between these two captured populations — i.e., **a co-occurrence measurement between tetraspanin status and tumor-marker status, not a capture-efficiency measurement for any single marker's own ligand-receptor pair.** Direct quotes: "Although EpCAM + EVs could be detected on all three tetraspanin capture spots at similar rates, biotin capture identified more EVs by approximately a tenfold difference. Her2 + EVs were identified with high frequency on all tetraspanin spots with approximately 5 times as many detected on the anti-biotin capture spot." And: "there may be a large percentage of non-tetraspanin expressing EVs that contain the bulk of these markers." Sample: SK-OV-3 (ovarian cancer cell line) EVs, N=3 capture spots per condition, ExoView/SP-IRIS platform.

**Cite prominently as motivation.** What they did NOT do, and what remains mine:
- No theory — they report 10×, can't explain *why* 10× rather than 3× or 50×, can't predict for untested proteins
- No prediction — every new protein/cell line/surface needs a new experiment
- No quantified trade-off — "use a combination" without saying which or at what yield cost
- Only three proteins on one cell line

Framing: *the bias is known and measured — here is the physical theory that explains its magnitude, predicts it for untested proteins, and quantifies the yield cost of the fix everyone recommends but nobody has sized.* **Explaining a known phenomenon is safer than discovering a new one** — it hands you real numbers to validate against. **This framing applies specifically to Aim 3b (the co-occurrence/independence model), not to a single-marker K_INTRA/z/k_geom calibration.**

**The nanostar validation paper: Linne, Heemskerk, Zwanikken, Kraft & Laan 2024**, *Soft Matter* 20:8515-8523, DOI 10.1039/d4sm00704b, PMC11484159. Open access.

DNA-origami nanostars with a fixed number of branched arms (valency `k`), each with a single-stranded "sticky end" that binds a complementary receptor on a supported lipid bilayer, imaged by TIRFM. Measured bound fraction Y as a function of receptor density σ_R, for k=1,3,4,10 (main valency sweep) and for three different sticky-end binding strengths at fixed k=6. Key findings, all directly relevant to this project's theoretical foundation:
- Selectivity α = d ln(Y)/d ln(σ_R) peaks at an *intermediate* valency, k=3 — not the largest valency tested (k=10). This is the headline external signature this project's Aim 2 leg 3 aimed to reproduce.
- The paper's SIMPLE independent-arms model (their Eq. 3-4, treating ligands as acting independently) does **not**, on its own, explain this k=3 optimum when fit to the real data — fitting it requires a different K_intra for each valency, which the paper itself calls "puzzling" and describes as evidence the simple model is "incomplete" or "inconsistent." Their real explanation is a second, extended model incorporating ligand-ligand pair interactions (cooperativity/competition), represented by a free energy term ΔG_c, fit via kinetic Monte Carlo (Gillespie algorithm) simulation — NOT the closed-form equations. ΔG_c becomes more *competitive* (arms interfering with each other) as valency increases: fitted values ΔG_c = −0.5, 0, +1.0 k_BT for k=3, 6, 10, with a SHARED K_intra=14×10⁻¹² and K_A=1×10⁻⁵ M⁻¹ across all three valencies (published Table 2).
- Binding strength also has an optimum (their k=6 sweep): too strong and the transition happens at too-low receptor density to resolve; too weak and multivalent effects wash out.
- **This project's reproduction (`src/nanostar_validation.py`) implements ONLY the simple independent-arms equations (Eq. 2-4), with representative per-k K_intra values chosen to decrease with k** — a mechanism the paper's own text indicates is NOT the real explanation for their data. This should be described as "a demonstration that the simple model's functional FORM can produce a qualitative k=3 optimum for some parameter choice," not as a faithful reproduction of the paper's own mechanism (unchanged since v6/v7).
- Their exact fitted numeric values for the SIMPLE model (Figure 2(e)'s table) remain unrecoverable as text (checked across PMC, RSC, and arXiv — all three embed this specific table as a graphic). The arXiv preprint (arXiv:2306.16885) is an earlier draft with DIFFERENT numbers (ΔG⁰=−7 kT vs. the published −8.4 kT) — do not mix numbers between versions.
- **A concrete, well-specified path to a tighter reproduction still exists, not attempted this session either:** implement the Gillespie kinetic Monte Carlo simulation described in the paper's Methods, using the published Table 2 values directly.

## Scope: what this project does and doesn't claim

Unchanged this session. Preserved in full from v4 through v10:

The project shifted from engineering (*build a thing that works*) to science (*determine what's possible and how to choose well*).

- **The model predicts both yield and selectivity** — same calculation. But **selectivity is the more trustworthy output** because it's a ratio: uncertainties in ligand density, contact area, incubation conditions, and detection efficiency affect tumor and normal predictions the same way and partially cancel.
- **The real deliverable is the trade-off curve**, not a single optimum. Few ligands → low yield, good selectivity. Many ligands → high yield, poor selectivity. The curve also shows which combinations are *physically impossible* regardless of engineering.
- **Relevance is asymmetric, state it honestly:** high specificity matters most for *diagnostics* (tumor EVs are a tiny minority in blood; low yield is fixable by running more sample, poor specificity isn't). For *therapeutic* filtering, yield matters much more.
- **Hard ceiling worth remembering:** if only 20% of vesicles carry a target, yield can never exceed 20%. Bulk measurements cannot see this.
- **A transferable idea worth developing:** a *computational* limit of detection. Given measured distributions, what is the minimum tumor-EV fraction that any affinity surface could detect?

**The decomposition that matters most.** Published copy numbers average over all vesicles including zeros, blending two different quantities:

> **copies per carrier = overall average ÷ fraction carrying**

Worked example (positivity fractions estimated — illustrative, not publishable): CD9 17.0 ÷ ~0.33 ≈ 52. CD81 1.6 ÷ ~0.10 ≈ 16. A tenfold apparent gap collapses to threefold.

**This decomposition has been run on the real digitized Lennon matched pair** — see "The decomposition" above for the full result. Unchanged this session.
